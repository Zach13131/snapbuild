# Снэпбилд — тестовое задание Junior Fullstack

Скопировал лендинг [snapbuild.ru](https://snapbuild.ru/) и добавил 6 новых секций. Хотел, чтобы новые блоки выглядели как часть того же сайта, а не как другой шаблон

## Ссылка на опубликованную страницу

- репозиторий: `https://github.com/<username>/snapbuild-test-task`
- GitHub Pages: `https://<username>.github.io/snapbuild-test-task/`

## Инструкция по локальному запуску

Нужны Node.js 20+ и npm.

```bash
cd frontend
npm install
npm run dev
```

Сайт откроется на http://127.0.0.1:5173

Те же команды можно запускать из корня репозитория: `npm run dev`, `npm run build`, `npm run preview`. Сначала нужен `npm install` в `frontend`.

Сборка для GitHub Pages:

```bash
npm run build
```

Готовая статика лежит в `frontend/dist`. Посмотреть её локально: `npm run preview`.

## Использованный стек

- React 19, TypeScript, Vite, Tailwind CSS, TanStack Query
- Тарифы и отзывы приходят через `fetch` из JSON: `frontend/public/api/plans.json` и `testimonials.json`. В файлах стоит `"mocked": true`. Отдельного сервера нет — GitHub Pages отдаёт только статику.
- Шрифт Satoshi. На исходном сайте в шаблонах он уже есть, а TT Commons Pro лицензионный, его не копировал.
- Публикация: папка `frontend/dist` на GitHub Pages

## Перечень добавленных секций

1. **Сценарии для команд** (`#audiences`) — после блока форматов. Маркетинг, дизайн, продажи, продукт.
2. **Этапы внедрения** (`#implementation`) — после безопасности. Диагностика → система → пилот → масштаб.
3. **Тарифы** (`#pricing`) — перед FAQ. Три карточки и переключатель месяц/год. Данные из mock JSON через TanStack Query.
4. **Отзывы** (`#reviews`) — слайдер: цитата, должность, компания, результат. Тоже mock JSON.
5. **Форма заявки** (`#contact`) — перед финальным CTA. Проверка полей, ошибки у каждого поля, экран успеха. На сервер ничего не уходит, отправка только на клиенте.

6. **Площадка «одна идея → набор»** (`#playground`) — после форматов. Бриф, сегмент и превью сайта, картинки, видео, баннера и презентации. Внешний API не вызывается: смена сегмента просто меняет тон текущего набора. На экране уже 800px блок прячется — на телефоне он получался слишком тесным.

Секции разные по устройству: сетка карточек, нумерованные шаги, тарифы, слайдер, форма и интерактивная площадка.

## Как анализировалась стилистика исходного сайта

Открыл [snapbuild.ru](https://snapbuild.ru/) и смотрел, как там устроены карточки, кнопки, заголовки и отступы. Дальше новые блоки собирал так же: светлый фон, белые карточки, тот же градиент на акцентах, крупный не очень жирный текст и узкая шапка по центру. Готовый UI-kit не брал, чтобы ничего не выбивалось

## Какие части исходной страницы удалось воспроизвести

Шапка (десктоп и меню на телефоне), первый экран со скриншотом продукта, бегущая строка логотипов, три карточки «одна платформа», вкладки Сайты / Изображения / Видео / Баннеры / Презентации, таблица сравнения, блок безопасности с фото, горизонтальный роадмап, FAQ, финальный CTA, футер, cookie-баннер. Тексты и картинки взял с исходного лендинга

## Что не удалось реализовать и почему

- Попиксельно исходник не собирал. Сделал ту же композицию на Tailwind и `clamp`, без копирования сгенерированного CSS
- Отдельный backend не делал. В задании сервер для формы не нужен, а GitHub Pages всё равно отдаёт только статику. Тарифы и отзывы читаются из JSON, форма остаётся на клиенте
- Картинки hero и продукта тяжёлые, как на оригинале. Отдельный CDN не подключал

## Что бы я улучшил при наличии дополнительного времени

- Нарисовать интерфейс продукта самому, а не вставлять растровый скриншот
- Ближе попасть в анимацию первого экрана и прогресс роадмапа
- Свои страницы privacy и agreement в репозитории
